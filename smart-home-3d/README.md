# บ้านอัจฉริยะ 3D

แบบจำลองบ้าน 2 ชั้น 3 มิติ (digital twin) สำหรับ **ดูสถานะ (monitor)** และ **สั่งงาน (operate)** อุปกรณ์ IoT ในบ้านผ่านเบราว์เซอร์ เชื่อมกับอุปกรณ์จริงด้วย MQTT

## เปิดใช้งาน

ไฟล์เดียว ไม่ต้อง build:

```bash
cd smart-home-3d
npx serve .          # หรือเปิด index.html ในเบราว์เซอร์ได้เลย
```

เปิดมาจะอยู่ใน **โหมดจำลอง** เบราว์เซอร์จำลองอุปกรณ์และเซนเซอร์ทั้งหมดให้ จึงลองใช้ได้ทันทีโดยไม่ต้องมีฮาร์ดแวร์

## ผังบ้าน

ขนาดตัวบ้าน 9 × 7 ม. สูง 2 ชั้น (ชั้นละ 3 ม.) หลังคาทรงปั้นหยา มองจากหน้าบ้าน:

| ชั้น | ครึ่งหลังของบ้าน (ซ้าย → ขวา) | ครึ่งหน้าของบ้าน |
|---|---|---|
| ชั้น 2 | ห้องนอน 1 · ห้องน้ำ · ห้องนอน 2 | โถงชั้น 2 กับหัวบันได |
| ชั้น 1 | ห้องครัว · ห้องน้ำ | โถงทางเข้า ประตูหน้าบ้าน และบันไดเลียบผนังหน้า |
| หน้าบ้าน | | ที่จอดรถ และประตูรั้วเลื่อนไฟฟ้า |

- **ชั้น 1** ห้องครัว (รวมโต๊ะทานข้าว) และห้องน้ำที่เข้าจากห้องครัว ประตูหน้าบ้านเปิดเข้าโถงทางเข้าซึ่งเป็นที่ตั้งบันได
- **ชั้น 2** ห้องนอน 2 ห้อง กับห้องน้ำตรงกลางที่มีประตูเปิดเข้าได้จากทั้งสองห้องนอน ประตูห้องนอนออกสู่โถงชั้น 2 ที่หัวบันได
- **หน้าบ้าน** ที่จอดรถหลังคาโปร่งแสงพร้อมประตูรั้วเลื่อนไฟฟ้า

ในเว็บสลับดูได้ 3 มุม: **ชั้น 1** (ซ่อนชั้นบน), **ชั้น 2** (ตัดหลังคาออก) และ **ภายนอก** (มีหลังคา) เวลาเลือกอุปกรณ์หรือห้อง ระบบจะสลับไปชั้นนั้นให้เอง

## ทำอะไรได้บ้าง

| ส่วน | รายละเอียด |
|---|---|
| โมเดล 3D | หมุน/ซูม/แพนได้ คลิกอุปกรณ์เพื่อเปิดแผงควบคุมบนโมเดล คลิกพื้นห้องเพื่อกรองรายการ |
| สถานะในโมเดล | ไฟสว่างตามระดับ dim, แอร์มีลมเย็น, พัดลมหมุนตามสปีด, ม่านขยับตาม %, ประตูรั้วเลื่อนตาม %, ประตูหน้าแง้มเมื่อปลดล็อก, พื้นครัวกะพริบแดงเมื่อแก๊สรั่ว |
| Monitor | กำลังไฟรวม (W), พลังงานวันนี้ (kWh และค่าไฟโดยประมาณ), อุณหภูมิ/ความชื้นแต่ละห้อง, ค่าแก๊ส, กราฟกำลังไฟ 2 นาที, อุปกรณ์ที่กินไฟสูงสุด |
| Operate | เปิด/ปิด, หรี่ไฟ, ตั้งอุณหภูมิแอร์, สปีดพัดลม, ม่าน %, ประตูรั้ว, ล็อกประตู |
| ฉาก | กลับถึงบ้าน / ออกจากบ้าน / เข้านอน |
| อัตโนมัติ | แก๊สเกิน 400 ppm → เปิดเครื่องดูดควัน, ล็อกประตูเองหลัง 30 วินาที, ใช้ไฟเกิน 4.5 kW → ปิดเครื่องทำน้ำอุ่น |
| บันทึก | ทุกคำสั่งและเหตุการณ์ พร้อมแหล่งที่มา (ผู้ใช้ / ฉาก / อัตโนมัติ / MQTT / เซนเซอร์) |

## สถาปัตยกรรม

```
 ┌────────────────────┐   WebSocket (wss)   ┌──────────────┐   TCP 1883   ┌──────────────────┐
 │ เว็บ 3D (Three.js)  │ ◄─────────────────► │ MQTT broker  │ ◄──────────► │ ESP32 / Tasmota / │
 │ index.html          │   /set  ▸  ◂ /state │ Mosquitto,   │              │ Zigbee2MQTT ฯลฯ   │
 └────────────────────┘                     │ EMQX, HiveMQ │              └──────────────────┘
                                            └──────────────┘
```

หน้าเว็บส่ง **คำสั่ง** ไปที่ `/set` แล้วรอ **สถานะจริง** จากอุปกรณ์ที่ `/state` โมเดล 3D จึงแสดงสิ่งที่อุปกรณ์ทำจริง ไม่ใช่แค่สิ่งที่กดไป

### รูปแบบ Topic

```
<base>/<ห้อง>/<อุปกรณ์>/set      คำสั่ง (JSON บางฟิลด์ก็ได้)
<base>/<ห้อง>/<อุปกรณ์>/state    สถานะเต็ม (retain)
<base>/<ห้อง>/sensor/state      {"temp":26.4,"hum":58,"gas":120}
```

รหัสห้อง: `hall` โถงทางเข้า, `kitchen` ห้องครัว, `bath1` ห้องน้ำชั้นล่าง, `landing` โถงชั้น 2, `bed1` ห้องนอน 1, `bath2` ห้องน้ำชั้นบน, `bed2` ห้องนอน 2, `carport` ที่จอดรถ

| อุปกรณ์ | topic | payload |
|---|---|---|
| ไฟ | `hall/light`, `kitchen/light`, `bath1/light`, `landing/light`, `bed1/light`, `bath2/light`, `bed2/light`, `carport/light` | `{"on":true,"level":0-100}` |
| แอร์ | `bed1/ac`, `bed2/ac` | `{"on":true,"setpoint":18-30}` |
| ทีวี | `bed1/tv` | `{"on":true}` |
| ม่าน | `bed1/curtain` | `{"open":0-100}` |
| ประตูหน้าบ้าน | `hall/door` | `{"locked":true}` |
| พัดลมเพดาน / เครื่องดูดควัน | `bed2/fan`, `kitchen/hood` | `{"speed":0-3}` |
| เครื่องทำน้ำอุ่น | `bath2/heater` | `{"on":true}` |
| ประตูรั้วไฟฟ้า | `carport/gate` | `{"open":0-100}` |
| เซนเซอร์แก๊ส LPG | `kitchen/sensor/state` | `{"gas":120}` (ppm) |

### เชื่อมกับอุปกรณ์จริง

1. ตั้ง broker ที่รองรับ WebSocket (เบราว์เซอร์ต่อ TCP ตรงไม่ได้) ตัวอย่าง Mosquitto:
   ```conf
   listener 1883
   listener 9001
   protocol websockets
   allow_anonymous false
   password_file /etc/mosquitto/passwd
   ```
   ถ้าเปิดเว็บผ่าน https ต้องใช้ `wss://` (ใส่ certificate ให้ listener 9001 หรือวาง reverse proxy ไว้หน้า)
2. แฟลช `firmware/esp32_room_node/esp32_room_node.ino` ลง ESP32 (ไฟห้องนอน 1 + DHT22) แก้ Wi-Fi, broker และ `BASE` ให้ตรงกับเว็บ ถ้าจะใช้กับห้องอื่นให้เปลี่ยน `ROOM` เป็นรหัสห้องด้านบน
3. ในเว็บ เปิด **การเชื่อมต่อ MQTT** → ใส่ URL broker และ Topic หลัก → **เอาเครื่องหมายถูกออก** จาก "ให้เบราว์เซอร์จำลองอุปกรณ์" → เชื่อมต่อ

ถ้าอยากผสมกัน (บางตัวจริง บางตัวจำลอง) ให้เปิดโหมดจำลองค้างไว้:

- อุปกรณ์ที่ส่ง `/state` ของตัวเองมา หน้าเว็บจะนับเป็นอุปกรณ์จริง ส่งคำสั่งไปที่ `/set` ของมัน และไม่เขียนทับสถานะ retain ของมัน
- อุปกรณ์ที่เหลือหน้าเว็บจำลองให้ โดยสถานะที่จำลองจะมี `"sim": true` ติดมาด้วย
- ค่าเซนเซอร์จริงจะแทนเฉพาะค่าที่ส่งมา เช่น ส่งแค่ `temp` ของห้องครัว เซนเซอร์แก๊สก็ยังจำลองต่อ

> broker สาธารณะ (`broker.emqx.io`) ใช้ทดลองเท่านั้น ใครรู้ topic ก็สั่งบ้านคุณได้ (รวมถึงปลดล็อกประตูและเปิดรั้ว) ใช้งานจริงต้องมี username/password, TLS และ ACL จำกัด topic ต่อ client

## ต่อยอด

- **Home Assistant / Node-RED**: ใช้ broker ตัวเดียวกัน แล้ว map entity เข้ากับ topic ด้านบน
- **เก็บประวัติ**: Telegraf → InfluxDB → Grafana จาก `+/sensor/state` และ `+/+/state`
- **โมเดลบ้านจริง**: ส่งออกแบบจาก SketchUp/Blender เป็น `.glb` แล้วโหลดด้วย `GLTFLoader` แทนกล่องใน `buildHouse()` ผูกอุปกรณ์ด้วยชื่อ object
- **เพิ่มอุปกรณ์**: เพิ่มแถวใน `DEVICES` (id = `ห้อง/อุปกรณ์`, `pos` วัดจากพื้นของชั้นนั้น) และถ้าเป็นชนิดใหม่ ให้เพิ่มตัวสร้างใน `BUILDERS` และ `buildControls()`
- **เพิ่มห้อง**: เพิ่มใน `ROOMS` พร้อม `floor` (0, 1 หรือ `'out'`) แล้ววาดผนังใน `buildHouse()`
